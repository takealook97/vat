# Change a command contract

## When to use this

A change touches what a command prints, what it exits with, which flags it
accepts, or what it writes to disk. All four are contracts somebody else may
already depend on, including scripts nobody in this repository can see.

## The rule this implements

A change to a command's output, exit code, or flags needs, in the same commit:
the code, its test, and the matching row in `docs/COMMANDS.md`. Split across two
commits, the reference describes a program that does not exist yet.

## Steps

1. Write the failing test first. For CLI behaviour that means a real command
   against a real temporary workspace — see the fixtures in `internal/cli`.
2. Make the change.
3. Update the command's `Usage` string so it names every flag the command
   registers, and no flag it does not.
4. Update the `## vat <name>` section in `docs/COMMANDS.md`.
5. If the change alters a file vat writes, update `docs/SPEC.md` in the same
   commit. It is normative and other tools may already read what it describes.
6. If a subcommand was added or removed, update the command table in
   `README.md`.
7. `make check`.

## What catches you if you skip a step

- `TestEveryTopLevelCommandHasASectionInTheReference` — a new top-level command
  with no `## vat <name>` heading.
- `TestTheReferenceDocumentsNoCommandThatDoesNotExist` — a heading left behind
  after a removal.
- `TestEveryFlagACommandRegistersAppearsInItsUsageLine` and
  `TestEveryUsageLineAdvertisesOnlyFlagsThatExist` — the `Usage` string and the
  registered flags, compared in both directions.
- `TestTheReferenceStatesTheExitCodesTheCodeUses` — the documented exit codes
  against the ones the code can return.

Shell completion is generated by walking the command tree, so a new subcommand
needs no completion edit.

## When it must stop

An exit code is the loudest part of the contract, because CI reads it and a
human does not. Changing what a code means — rather than adding a new one — is a
decision about everybody's pipelines, not a refactor. Report it and let a human
choose.

The same applies to removing a flag. Deprecating it in the help text costs
nothing; removing it breaks a script silently.
